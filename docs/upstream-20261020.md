# Upstream integration, 2026-10-20

Branch: `renoir`. Source range: `1dc05376f8942f681a514709bf6a565848c97f0e` through `f421d04` (198 commits, including merges). Checkpoint: `9d4be59`; recovery branch: `backup/renoir-before-upstream-20261020`.

## Scope and method

This is a selective integration of the complete upstream endpoint source diff, using three-way merges against the Renoir branch. It is not a merge that claims the excluded storage history was accepted. Mixed commits are split by behavior. Intermediate changes superseded or reverted upstream are represented by their final endpoint, not replayed independently.

Included: camera capture graph, preview/shutter/stills, sensor tuning and ISP; optional Sileo/Procursus and RAM prefix; persona and process gates; multiple injection libraries and app diagnostics; UI/backdrop fixes; AIR frontend, ir3 rounding and compiler checks; workspace and resident payload provenance tooling. Existing Renoir GPU, Wi-Fi, audio, touchscreen, haptic and clock-offset work is retained.

Excluded: APFS implementation/tools, persistent var store, UFS write support, flash loader hooks and instructions. Root and system images remain packfs. The small root must be **uncompressed** because early GPU firmware lookup cannot decode chunked packfs. No phone partitions were accessed during this integration.

Upstream binary snapshots target their upstream source and may contain excluded storage behavior. They were not imported. Validation uses the locally built kernel, loaders, Mesa and userland; the tracked kernel and userland fallbacks were refreshed from those local builds after host checks and QEMU reached SpringBoard. UEFI was not refreshed. Rebuild Mesa locally for the optional GPU/AIR path; its large libraries are not part of prebuilt/userland.

## Renoir adaptations and limits

Native Shima CSID/IFE580, PHY and rails, EGPIO and DMA stride are retained. Main/front use native gain limits and GBRG order, Renoir-specific tuning, and DW9800 initialization (register 07=0x0b). Vendor files are optional, hash-pinned by `tools/renoir-camera-tuning.json`, downloaded with `tools/fetch_renoir_camera.py --tuning`, and remain untracked. Renoir uses LSC40, not Redwood's LSC34. The camera ABI remains 120 bytes, with one formerly reserved byte identifying the platform.

Reader pin/drain synchronization prevents freeing DMA slots while a read copies their contents. Hardware streaming remains explicitly experimental: real Renoir cam5 requires `cam_stream_test=1`; only tested main/front indices are admitted. QEMU's `cam_fake=1 cam_profile=renoir` exercises descriptors and the app pipeline without camera MMIO. This cannot validate sensor exposure, autofocus, orientation or real CSI streaming. Earlier standalone RAW captures on the phone are not proof of the new Camera.app integration.

Optional package-manager changes use a ramfs prefix at `/private/preboot/jb-rw/procursus`; application registration needs this pathname, but it does not imply APFS or persistence. A normal image has no bootstrap unless explicitly built with one.

## Verification

- XNU, Redwood/Renoir loader, Mesa/AIR and complete packfs userland source builds passed.
- Host tests exercise actual camera board, power, clock, CSID580, IFE580, ring and reader-lifetime helpers. Lifetime runs concurrent readers under ASan/UBSan, 100 iterations. ISP and status-bar exec injection tests passed. Additional native-profile checks passed: five pinned vendor blobs, four LSC40 exports, main/front GBRG mode tables, AF timing and every initialization write failure (without voting Redwood rails).
- AIR suite passed: reader 456/456; texture operations 35/35. Approximate operations and unsupported declarations have separate exclusions in the logs. This is compiler/softpipe coverage, not Metal or Adreno hardware certification.
- Final QEMU reached a correctly rendered SpringBoard home screen with the latest kernel and packfs images; camera-app interaction is recorded below after the run. Real-phone regression is pending; the phone is disconnected. No flash or erase command was issued.

QEMU screenshots must be captured by `qemu/screendump.sh`: raw PPM rows have padding; treating them as width*3 bytes produces misleading skew and apparent rendering corruption.
