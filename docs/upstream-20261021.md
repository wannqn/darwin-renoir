## Imported behavior and adaptation

- AIR: zero initializer spellings, library-function wrappers, sampler-pointer
  allocation and numeric reference/report tools. These are compiler/runtime
  fixes; upstream Adreno results are not device validation of Renoir A642.
- Services: demand-launched apsd, appstored, cloudd, itunesstored,
  installcoordinationd and mobileactivationd, only if their executables exist in
  the RAM image or extracted cryptex. CommCenter stays denied. Missing full-volume
  executables are not advertised as present.
- Wi-Fi daemon enabled by default; WIFID=0 omits it. Existing Renoir manual join,
  native ath11k/PCIe path and early 80 MiB DMA reservation remain unchanged.
- Account/store/FairPlay probes and optional injection libraries. STOREFRONT is
  unset for the normal build. This does not implement an Apple device identity,
  Secure Enclave, successful account sign-in or a working App Store.
- Kernel systrace optionally prints MAC policy/request and sysctl MIB details.
  Existing generic-board 64 MiB MMIO VA reservation and first-panic capture remain.
- Existing Renoir main-camera full-field mode1, native front mode, DW9800 timing,
  drained-ring restart, rail dispatch, audio/haptics and +24 status-bar adjustment
  were retained. No incoming hardware-driver changes were present in this range.
- Repository instructions imported: origin now means GitLab; GitHub remote renamed
  github. Current local branch dev/wannq starts at the same HEAD as renoir and has
  only uncommitted changes. renoir was not moved. No publication happened.

Excluded from mixed build/job changes: FLASHBOOT recipe, root-volume listing
availability, root.apfs/flashboot.apfs behavior. Both images remain packfs, small
root uncompressed for early firmware reads. No upstream binary snapshots imported.

not establish internet connectivity. The same recipe showed this limitation in
the preceding camera/MMIO QEMU run; no new radio-driver behavior is inferred.
